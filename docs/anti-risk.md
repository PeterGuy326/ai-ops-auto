# 平台风险与合规边界

`ai-ops-auto` 的目标是把发布变得有审核状态、可限流、可停止和可审计，不是规避平台风控。
没有任何浏览器引擎、代理或“仿真人”参数能保证不被检测、不限流或不封号。

Legacy 管理 API 仍共用一个全权限 `API_KEY`，其 `approve` 记录不能证明审批者一定是人。Agent
contract v1 已把非人调用者和 `human` 审批 principal 拆开，并禁止请求者自签；但 `human` 凭证是否
真的由人控制，仍取决于部署者把它放在 Agent 无法读取的 SSO、审批系统或硬件密钥边界。
`AUTO_PUBLISH_ENABLED` 只控制后台扫描，不是全局授权开关。

使用者需要自行确认平台条款、授权、内容合规、隐私和适用法律。平台不允许自动化时，不应启用对应 Publisher。

## 主要风险

| 风险 | 后果 | 控制面策略 |
|---|---|---|
| 未授权/误发布 | 公开错误内容、品牌/合规事故 | 审核状态流 + 外部 human gate + 后台自动发布默认关闭 + 执行留痕 |
| 重复发布 | 垃圾内容、重复扣额、账号处置 | 原子 claim、幂等任务语义、服务端结果校验 |
| 登录态过期 | 发布失败或扫码阻塞 | 账号健康检查、明确 `EXPIRED`、人工重新授权 |
| 配额/频率过高 | 限流、失败或账号处置 | 每账号日限额、最小间隔、有界重试 |
| 平台 UI/API 变化 | selector 失效或误判成功 | 保守能力矩阵、版本锁定、canary、失败关闭 |
| 凭证泄露 | 账号接管、数据泄露 | DB credential 用 Fernet；磁盘 profile/OAuth/cookie 另做文件权限、主机隔离；日志脱敏、最小权限 |
| 内容重复/权利问题 | 降权、侵权投诉 | 内容查重、资产来源记录、人工审核 |

## 推荐优先级

1. **官方 API/官方工具**：有可用官方发布接口时优先使用，遵循审核、配额和权限模型。
2. **人工辅助**：对不可逆、高风险或平台不允许自动化的步骤，只生成草稿/预览，由人提交。
3. **浏览器适配器**：只在平台条款和账号授权允许时使用，且必须有测试账号、canary 和紧急停止。

Playwright、Chrome channel、Patchright 或 Camoufox 在本项目中是浏览器兼容性选项，不是“不可检测”承诺。

## 默认控制

| 配置 | 默认 | 接受范围 | 含义 |
|---|---:|---:|---|
| `AUTO_PUBLISH_ENABLED` | `false` | 布尔值 | worker 不自动扫描/执行真发布 |
| `GITHUB_PAGES_DRY_RUN` | `true` | 布尔值 | 只预览，不写站点、构建或 push |
| `PUBLISH_MAX_PER_DAY` | `2` | `1..50` | 每账号单日上限；应按平台政策调低 |
| `PUBLISH_MIN_INTERVAL_SECONDS` | `14400` | `60..604800` | 同账号发布间隔下限（秒） |
| `NURTURE_DAYS` | `7` | `0..365` | 业务侧新账号冻结窗口；不代表平台规则或成功保证 |
| `PUBLISH_JITTER_SECONDS` | `600` | `0..86400` | 排程抖动窗口（秒），用于分散同时到期任务 |

这些参数是事故半径限制，不是平台风控规避方法。
越过表中范围会在配置加载时直接失败；范围只是控制面安全护栏，不代表平台允许对应频率。
`AUTO_PUBLISH_ENABLED=false` 不禁用 `/jobs/{id}/run` 等显式管理操作；不要把它当作全局 kill switch。

## 真平台 canary

每次平台、浏览器或上游工具升级后：

1. 保持全局自动发布关闭。
2. 使用专用测试账号和无敏感/无商业影响的内容。
3. 一次只测一个 Publisher、一个内容类型和一条任务。
4. 在平台作品管理端核对可见性、post identity 和实际数量。
5. 记录上游 commit、OS/浏览器版本、时间和失败现象，更新 [能力矩阵](platform-capabilities.md)。
6. canary 失败则保持关闭，不通过无限重试来“碰成功”。

## 事故响应

发现误发、重复发布、账号异常或平台结果无法确认时：

1. 停止 `ai-ops worker`，设置 `AUTO_PUBLISH_ENABLED=false`，并撤销或隔离显式管理执行端点。
2. 不要立即重发“覆盖”；先在平台端确认真实状态。
3. 保留 PublishJob/审计日志，记录影响的账号、时间窗和内容；对外分享前脱敏。
4. 如果涉及凭证，立即吊销/轮换，并按 [SECURITY.md](../SECURITY.md) 处理。
5. 确认根因和幂等保护后，使用测试账号重新 canary。
